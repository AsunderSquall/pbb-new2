# 无需 Agent 的本机自动测评

双击 `tune_quick.bat`（精简版）或 `tune_full.bat`（完整版），输入以前完整测号的速度，单位 **T/day**，允许小数，例如 `6.1`；再输入期望测试时长，推荐 **20分钟**，回车默认20。编译时间单独统计，不计入这个软目标；超过时长继续完成全部计划的邻居测试和最终确认。脚本不调整线程数，使用所选配置的线程数。

也可以直接运行：

```powershell
.venv/Scripts/python.exe autotune.py --mode quick --config config_football.yaml --speed 6.1 --minutes 20
.venv/Scripts/python.exe autotune.py --mode full --config config_football.yaml --speed 6.1 --minutes 20
```

需要项目 Python 依赖、有效的 Python 核心模块及 GCC/g++；暂不支持 MSVC/icpx 调优。离线包的批处理优先使用随包 Python。测评前暂停其他测号任务，清除自定义 `PBB_CXXFLAGS` / `PBB_SRC_DIR`。多个前缀各自配置枚举范围的模式暂不支持。

## 持久构建配置

发布包最外层 `config/build_config.json` 初始为 `tested: false`、`status: "none"`，其他开关为当前默认值。`config.yaml`、足球配置和配置示例也放在这个 config 文件夹，不放在 source 或 PBBMonitor/_internal 中。开发源码目录未建立 config 文件夹时兼容原根目录位置。未测试时 native 构建使用原有默认参数。普通/UI 引擎通过 `build.py` 读取同一份配置；Python 核心不使用这些引擎优化开关。

测评从有效的已测试配置开始，否则从默认值开始。每接受一项改动，后续候选就以这个累积组合编译和测试，不再分别与最初默认比较。中间状态写入测评目录的 `build_config.progress.json`，不会提前把未完成组合用于正式引擎。最终组合还必须与本轮起点重复确认；不通过就保留起点。

只有完成测试和两个引擎的正确性验证后，才把最终选择写入发布包的 `config/build_config.json`（开发目录兼容原根目录），标记 `tested: true` / `status: "complete"`。没有新增收益时也会记录已测试的起点。配置绑定本机、编译器路径和源码哈希；换机器或源码变化时回到默认参数。`PBB_CXXFLAGS` 仍有最高覆盖优先级。

测试完成后仍须 Rebuild 一遍：默认只发布构建选项，实际引擎必须重建才应用它。可关闭监控器后运行外层 rebuild.bat，或在 UI 勾选 Rebuild 引擎后启动。二进制清单会因选择变化而失效，不需要专用参数启动器。本项目开发源码入口为 start_ui_native.bat。

通用发布包始终写入未测试的默认配置，不能带走打包机器的选择；portable 构建忽略本机选择。监控器 Rebuild 与源码测评共用 `config/build_config.json`。pure 与 environment 是独立组件：已有环境只更新 pure，没有环境时下载两者并将 runtime 放在 source 的同级。

## 测试量与预算

脚本根据可用测试时间、预计邻居数、配对轮数及最终确认预留，分配每个完整任务的时间。枚举范围长度按下式计算，并向下取整到一百万的整数倍，最少一百万：

`范围长度 = T/day × 0.9 × 10^12 ÷ 86400 × 单任务秒数 ÷ 前后缀组合数`

每次接受新组合后，用实测速度重新计算后续任务量。每一对比较仍使用相同候选范围、种子和输出设置。输入速度只负责估算初始量，不作为比较成绩。计算记录在 `test_plan.json`，实际每轮参数保存在 `runs/`。

软目标包括引擎正确性验证、预热及性能测量，不包括编译；总等待时间可能超过输入分钟数。不会因目标时长耗尽而跳过候选或停止引擎，仍完成最终确认与交付验证。用户中断或真实错误才保留 incomplete.json、不发布半成品配置。

## 候选与验证

精简版包括 7640HS 包的 reg512、guard512，再比较全局 AVX2、分段 KSA、编码及复制组合、属性 min/max、LTO。完整版另加入 mixed512、reg256、向量宽度256、循环展开，并反向复查。先检查 CPU 能力，不支持的方案跳过；先测 native 过滤，避免提前禁用 AVX-512。过滤方案编号0/1/2/3/4对应原版/guard512/reg512/mixed512/reg256，普通向量写入保留容量回退。

邻居试验精简版两对且两对更快，完整版三对且至少两对更快；配对中位收益默认至少0.3%，可用 `--minimum 0.001` 改为0.1%。最终确认精简版四对至少三快，完整版六对至少五快。它是 O(n) 局部搜索，避免明显较慢的组合，不保证穷举最优。

默认测 UI 完整任务性能，`--target standard` 可测普通引擎；另一目标验证正确性，不把一个目标的性能结论冒充另一个目标的实测。低阈值仅用于非空正确性对拍；性能保留配置中的评分、门控、潜力、收集、结果输出，终端进度日志统一关闭。

正确性覆盖五种字节宽度、前后缀、队伍、全部评分族、非空数值输出、收集、跨 chunk/尾批和复制边界。精简版覆盖枚举模式1/2，完整版覆盖1/2/3/4。过滤函数另比较随机排列的前 max_len+1 项属性、完整256字节技能数据、技能重建和容量哨兵，包含 max_len=30及0..127边界。潜力保留原阈值，没有强制证明每种潜力均命中，也没有比对所有其他中间状态。UI Top同分维持原到达顺序，正分名字差异必须证明为同分。

## 安装与回退

每次在 `build/autotune/日期_时间/` 隔离保存源码、配置、完整编译命令、参数、输出、哈希、每轮速度及报告，不碰生产输出或 resume。完成测试默认只发布构建配置，不立即替换正式二进制。关闭占用引擎的程序后，安装已验证的普通/UI 二进制：

```powershell
.venv/Scripts/python.exe autotune.py --install-from build/autotune/日期_时间
```

可用 `--apply` 在测评成功后直接安装；用 `--no-write-config` 做完全隔离的评估，保留根目录配置。安装核对本机、源码、结果状态和二进制哈希，备份原二进制、清单及构建配置，失败时恢复。

安装后回退（先关闭引擎）：

```powershell
.venv/Scripts/python.exe autotune.py --rollback-from build/autotune/日期_时间
```

回退拒绝覆盖安装后再修改的文件。只发布配置、没有安装时，可将本轮 build_config.before.json 恢复到发布包的 config/build_config.json（开发目录原根位置），然后 Rebuild。同一结果目录只能安装一次。
